= カスタムダッシュボードについて
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
クラウドおよびストレージ管理者にとって、カスタムダッシュボードは、管理するシステムとワークロードを明確に把握するのに役立ちます。あらかじめ用意されたレイアウトに限定されることなく、自分の仕事内容、優先順位、ビジネス目標に合ったビューを構築し、カスタマイズすることができます。

カスタムダッシュボードは、AIを使用してWorkload Factory環境のパーソナライズされたビューを作成します。監視したい内容を平易な言葉で説明するだけで、システムがニーズに基づいて自動的にビジュアルチャートを作成します。

Workload Factoryアカウントのすべてのユーザーは、すべてのカスタムダッシュボードを閲覧できます。この共有設定により、チームは組織全体で連携し、同じ運用情報を共有できるようになります。



[[why-use-custom-dashboards]]
== カスタムダッシュボードを使用する理由

Workload Factoryのユーザーは、多くのワークロード、環境、および優先順位を管理しますが、標準ダッシュボードにはあらかじめ設定されたビューしか表示されません。カスタムダッシュボードは、いくつかの運用上の課題を解決するのに役立ちます：

* *重要な質問に素早く回答する*：一般的なシステム統計ではなく、最も重要な質問や理解のギャップに焦点を当ててください。
* *今重要なことを監視する*：固定された一連のヘルス指標ではなく、現在の優先事項に合致する指標を追跡します。
* *技術データとビジネス成果を結びつける*：システムのパフォーマンスが業務やビジネス目標にどのように影響するかを示します。
* *ツール間の切り替えは不要*：すべての関連情報を1か所で確認できます。ツール、ページ、エクスポートを切り替える必要はありません。




[[what-you-can-do-with-custom-dashboards]]
== カスタムダッシュボードでできること

セットアップ中、AIガイドダイアログでは以下の項目を定義できます：

* 監視対象のワークロードとリソース
* 仕事にとって重要な主要指標
* 比較対象となる時間範囲と期間
* 地域別、ワークロード別、またはその他のカテゴリ別の表示
* 追跡および表示する必要のあるルールまたは要件




[[considerations-and-limitations]]
== 考慮事項と制限事項



[[aws-credentials-and-permissions]]
=== AWS認証情報と権限

カスタムダッシュボードを作成または表示するには、監視対象のリソースに対する適切なAWS IAM権限が必要です。Workload Factoryアカウントが、ダッシュボードで使用されるデータソースへの読み取りアクセス権を持っていることを確認してください。

ダッシュボードを構築するために、Workload Factory は読み取り専用の AWS 認証情報を使用します。これらの認証情報では、次のサービスに対して `fsx:DescribeVolumes`や `fsx:DescribeFileSystems`などの読み取り操作のみが許可されます：EC2、FSx、CloudWatch、Resource Groups Tagging API、バックアップ、CloudWatch Logs、KMS、およびEFS。

link:add-credentials.html["AWS認証情報を追加し、IAM権限を設定する方法を説明します。"^]。



[[link-to-fsx-for-ontap]]
=== FSx for ONTAP へのリンク

Workload Factory は、FSx for ONTAP ファイルシステムに接続するためにリンクが必要です。リンクは、Workload Factory と 1 つ以上の FSx for ONTAP ファイルシステムとの間に信頼関係と接続性を確立します。これにより、Amazon FSx for ONTAP API では利用できない ONTAP REST API 呼び出しを通じて、特定のファイルシステム機能を直接監視および管理できます。

https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["リンクの作成方法を学ぶ"^]。



[[read-only-design]]
=== 読み取り専用設計

カスタムダッシュボードは読み取り専用です。ストレージ設定やワークロード設定を変更することはできません。これにより、誤って設定を変更することなく、システムを監視できます。



[[limitations]]
=== 制限事項

カスタムダッシュボードには、現在以下の制限事項が適用されます。

* Workload Factoryアカウント以外でダッシュボードを共有することはできません。




[[demo-environment]]
=== デモ環境

Workload Factory のデモアカウントをご利用の場合は、あらかじめ構築されたダッシュボードがいくつか利用可能です。これらのダッシュボードは、カスタムダッシュボードで何ができるかを理解するのに役立ちます。各ダッシュボードには、ディザスタリカバリのステータス、リージョンをまたいだ容量とコスト、ストレージ保護ルールが遵守されているかどうかなど、一般的な監視ニーズが表示されます。



[[sample-prompts]]
=== サンプルプロンプト

以下の例は、監視ニーズを平易な言葉で説明する方法を示しています。

* *災害復旧監視*：「AWSでオンプレミスシステムの災害復旧ソリューションをセットアップしています。米国東部リージョンの災害復旧サイトにおける、オンプレミスリソースの完全なリストと、それぞれのステータス（構成済み、アクティブ、正常かどうかを含む）を確認したいと思います。」
* *複数リージョンの容量とコスト*：「複数のクラウドリージョンとアプリケーションにまたがるストレージを管理しています。割り当てたストレージ容量、使用中の容量、およびコストについて、リージョン別・アプリケーション別の詳細を含めて明確に把握したいと考えています。」
* *ストレージ保護コンプライアンス*：「組織の基準に基づいて、新しいストレージ保護戦略を策定しています。以下の要件を満たしているかどうか、すべてのファイルシステムを表示してください：すべてのファイルシステムを表示し、それらが以下の要件を満たしているかどうかを確認してください：
+
** データベースのワークロード：ボリュームごとに1日12回のスナップショット、および週2回の改ざん防止スナップショット。
** NFSおよびSMB共有：ボリュームごとに7つの日次スナップショットと、週1つの改ざん防止スナップショット。
** ARPはすべてのボリュームで有効にする必要があります。」
